# Security Policy

## Supported versions

Only the [latest release](https://github.com/brandy2015/XYZLCU/releases/latest) receives security fixes.

## Reporting a vulnerability

Please **do not** open a public issue for security problems. Report them privately through GitHub's
[private vulnerability reporting](https://github.com/brandy2015/XYZLCU/security/advisories/new)
(Security tab → "Report a vulnerability"). Include the version, macOS version, steps to reproduce and the impact.
You should get a response within a few days.

## Scope notes

Version 0.8.0 keeps all consumer computer operations unavailable. Generic window/element incarnation, current protected-surface continuity, authenticated consumer bootstrap and exact no-prompt launch providers are not established. Legacy capture, AX content, input/PID/global routes, activation, permission requests and aliases refuse before dispatch; no global override relaxes that gate. The daemon starts no display prewarm or capture producers.

Process observations are diagnostic metadata, not permission grants, atomic OS attestation or authenticated content proofs. Local ad-hoc signatures establish no publisher/distribution trust. TCC belongs to the actual process and responsible launching context; it is observed without prompting. Protocol 2 never receives sensitive proof/key FDs. The C client executes only its sibling core, ignoring historical core-path environment overrides.

Protected seeds with unreviewed signers remain conservatively denied. Fixed-path 0600 owner policy/0700 directories, no-follow/link checks and revision/digest state reduce accidental substitution; they do not sandbox an arbitrary same-UID process that can rewrite binaries, policy and state. XYZStudio must retain trusted owner high-water state and immutable self/helper/category exclusions before any future admission. A flat denylist cannot classify browser-hosted sensitive content or authenticated helper families.

Reports about schema/FD/socket handling, policy continuity, target reuse, stale/partial payload publication, cancellation and MCP/batch entry-point bypasses are especially welcome. See [verification](docs/IDENTITY_PROOF_VERIFICATION.md) for built behavior, test evidence and deferred gates. Reconnect old resident MCP sessions after installation; replacing disk files does not reload already mapped executors.
